    02 / Data, models, services, delivery

    Anything I build has to be measurable. If I can't name the number it moved, it isn't finished.

    I'm a Computer Science undergraduate at IIIT-DM Kancheepuram, and most of what I build sits between a language model and something that has to keep working on Monday morning — retrieval pipelines, evaluation harnesses, agent environments, the APIs underneath them.

    Last summer I interned at Chella Software in Madurai, where I wrote a binary data pipeline in C that merged structured .DAT files from production servers so regression testing across financial data streams could run automatically, and a Python tool that generated 550 synthetic finance portfolios across equities, futures and options to stress-test the analytics downstream of it. Neither was glamorous. Both were the reason other people's work stopped breaking.

    I don't think of research and engineering as separate jobs. A RAG pipeline that indexes a thousand campaign records is a research question until someone has to wait on it — then it's a latency budget, a chunk size, and a decision about which embedding model earns its memory.
